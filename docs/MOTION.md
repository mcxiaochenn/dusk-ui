# Dusk UI — 动效规范

Dusk UI 的动效目标是**连续与克制**：状态切换连贯、浮层出现消失有运动关系、按下回弹柔和。**不做物理液体模拟、实时折射、WebGL，也不做跟随鼠标扭曲整页。**

共用参数集中在 `src/lib/motion.ts`，**组件内不写裸毫秒数与裸弹簧参数**。

---

## 1. 时长档位

| 档位 | 值 | 用途 |
| --- | --- | --- |
| `DURATION.feedback` | 150ms（约 120–180） | 状态反馈：hover / focus / active |
| `DURATION.dialog` | 200ms（约 150–220） | 弹窗与通知进退场 |
| `DURATION.enter` | 300ms（约 250–350） | 内容入场 |
| `DURATION.stagger` | 50ms（约 40–60） | 列表错峰单步 |

CSS 侧对应 `--duration-feedback` / `--duration-dialog` / `--duration-enter` / `--duration-stagger`，二者必须一致。

**列表错峰总延迟上限** `STAGGER_MAX_TOTAL = 240ms`。超过上限后剩余元素共用同一延迟，避免长列表迟迟无法交互。用 `staggerDelay(index, total)` 计算，不要自己累加。

---

## 2. 缓动

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--ease-standard` | `cubic-bezier(0.25, 0.1, 0.25, 1)` | 通用，状态反馈 |
| `--ease-entrance` | `cubic-bezier(0.16, 1, 0.3, 1)` | 入场，到达柔和 |
| `--ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | 退场，快速离开 |

## 3. 弹簧参数

### 3.1 三个参数的含义

- **stiffness（刚度）** — 数值越大回弹越快，越「急」。过大会显得生硬。
- **damping（阻尼）** — 数值越大越快停住。过小会来回振荡。
- **mass（质量）** — 数值越大越沉，启动与停止都更慢。

damping 接近**临界阻尼**时不振荡。Dusk UI 的配置分为两类：
- **接近临界阻尼**：用于指示器、入场、弹窗。几乎无可见回弹。
- **低刚度低质量**：仅用于 Dock 尺寸变化，需要跟手。

### 3.2 按角色区分

| 常量 | stiffness | damping | mass | 用途与理由 |
| --- | --- | --- | --- | --- |
| `SPRING.dock` | 150 | 12 | 0.1 | Dock 尺寸随鼠标连续变化，需要跟手；低质量让它响应快 |
| `SPRING.indicator` | 420 | 34 | 0.6 | 分段控件指示器移动，短促且几乎无回弹 |
| `SPRING.enter` | 320 | 28 | 0.7 | 内容入场淡入 + 小幅上移 |
| `SPRING.pop` | 380 | 30 | 0.7 | 弹窗与通知的极小幅度缩放 |
| `SPRING.press` | 500 | 26 | 0.5 | 按钮按下回弹，干脆利落 |

### 3.3 位移幅度

一律**小幅度**：

- 入场：`{ opacity: 0, y: 8 }`（`ENTER_INITIAL`）—— 上移 8px。
- 弹窗与通知：`{ opacity: 0, scale: 0.97 }`（`POP_INITIAL`）—— 缩放仅 0.97。
- 按钮按下：`scale: 0.98`。

## 4. 液态交互规则

「液态」指**交互的连续性**，不是视觉特效。

### 4.1 SegmentedTabs：同一块表面在移动

选中指示器使用 Motion `layoutId`：

```tsx
{selected ? (
  <motion.span
    layoutId="dusk-segmented-indicator"
    transition={SPRING.indicator}
  />
) : null}
```

要点：

- 快速连续点击时，Motion 从**当前实际位置**继续过渡，不会跳回起点。
- **文字不参与缩放**：指示器与文字分处两层，文字始终清晰，不会被拉伸。
- 键盘与触屏的视觉状态与鼠标完全一致。

### 4.2 FloatingDock：鼠标移动时相邻元素平滑响应

距离映射（思路参考 Aceternity UI的 Floating Dock，**独立实现**）：

```
distance = 鼠标X − 按钮中心X
distance ∈ [-120, 0, 120]  →  尺寸 ∈ [40, 76, 40]
```

用 `useSpring` + `SPRING.dock` 平滑，鼠标快速划过时相邻按钮依次响应而非跳变。

#### 布局开销（必读）

按钮的**宽高是真实布局尺寸**，因此放大会把相邻按钮推开，而不是让它们压盖。

- **代价**：Dock 宽度随放大实时变化，会触发布局重排。
- **影响范围**：仅 Dock 内部的若干按钮，页面其余部分不重排。
- **居中保证**：外壳用 `justify-center` 居中，实测静止与放大状态下中心点均保持在内容区正中（验收脚本已校验漂移 < 1px）。
- **溢出防护**：外壳留 `py-3` 余量，避免放大后贴边或裁掉焦点环。

触屏端与 `prefers-reduced-motion` 下完全不做尺寸动画，尺寸恒定。

### 4.3 Button：按下轻微缩放

hover 调整背景或边框；按下 `scale: 0.98`，用 `SPRING.press` 恢复。**禁止明显位移、夸张弹跳或文字模糊。**

### 4.4 Toast 与 Dialog

- 轻微缩放 + 透明度过渡。
- 弹簧只产生小幅、短暂回弹。
- **关闭过程有明确终点**，不拖泥带水：退场用较快的 `TWEEN.feedback`（150ms），不用弹簧拖尾。

## 5. 优先动画属性

**优先 `opacity` 与 `transform`。** 这两个属性可由合成器处理，不触发重排。

避免动画：`width`、`height`、`top/left/right/bottom`、`margin`、`padding`，以及持续动画 `filter`、`backdrop-filter`、`box-shadow`。

例外：Dock 的宽高变化是**刻意**的布局动画（见4.2），因为推挤效果依赖真实尺寸。

---

## 6. 减弱动画

`prefers-reduced-motion: reduce` 时：

| 场景 | 正常 | 减弱后 |
| --- | --- | --- |
| 内容入场 | 淡入 + 上移 8px | 仅淡入，或即时出现 |
| 弹窗 / 通知 | 淡入 + 缩放 0.97 | 仅淡入 |
| 分段控件指示器 | 弹簧移动 | 瞬时切换 |
| Dock 放大 | 随鼠标连续缩放 | 尺寸恒定，不放大 |
| 按钮按下 | 缩至 0.98 | 无缩放 |
| 颜色过渡 | 150ms | 立即生效 |

**关键原则：减少动画时仍保留清楚的状态反馈。** 取消位移与回弹，但不能让用户看不出当前选中项、加载状态或通知类型。

实现方式：组件内用 `useReducedMotion()` 判断，传入 `duration: 0` 或直接置 `false` 跳过；全局 CSS 另有兜底（`globals.css` 中的 `@media (prefers-reduced-motion)` 强制压缩过渡时长）。

---

## 7. 禁止做法

- ❌ 大面积循环漂浮动画。
- ❌ 长时间或持续动画的模糊（`filter: blur` 循环）。
- ❌ 夸张回弹（大幅 overshoot、来回振荡）。
- ❌ 每次刷新都重播整页入场动画。
- ❌ 给大量元素永久添加 `will-change`。
- ❌ 动画化 `backdrop-filter` 或大范围阴影。
- ❌ 因为视觉效果破坏焦点可见性、点击区域或滚动。
- ❌ 为动画建立复杂的配置系统或配置面板。

---

## 8. 性能诚实说明

本文档**不声称**「GPU 加速所以没有性能成本」，也**不声称**已达到 60fps 或完成低端设备优化——这些都需要实测数据支撑，本仓库目前没有相关测量。

已知的实际开销：

- Dock 尺寸动画会引起 Dock 内部重排（见 4.2），已通过限定影响范围控制。
- 多处 `backdrop-filter` 同时存在时合成成本上升，已通过移动端降低模糊值与限制玻璃使用位置缓解。
